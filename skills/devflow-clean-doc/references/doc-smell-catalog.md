# 文档异味目录

每条异味给出识别特征、它让评审者付出什么代价、修法和 before/after。例子都来自 DevFlow 文档的真实形态。修法一律限制在表达层；涉及规范层的判定见 `rewrite-protocol.md`。

## 速查

| 异味 | 识别 | 审查代价 | 修法 |
|---|---|---|---|
| 空转句 | 删掉后信息量不变 | 占用预算，无法反驳 | 换成可观察事实或删除 |
| 模板复读 | 正文在复述模板对该章节的说明 | 看不出是没分析还是没写 | 写实际内容或可审查的 N/A 理由 |
| 结论后置 | 判断埋在段落中后部 | 每段都要读完才知道要不要细看 | 判断提到段首 |
| 术语漂移 | 同一对象两个以上名字 | 先猜是不是一个东西 | 统一并登记术语表 |
| 代词悬空 | 跨段的 `其`、`该机制` | 回读定位 | 写名字或 ID |
| 名词化长句 | 60 字以上、动词被包成名词 | 读两遍才能复述 | 拆句 + 还原动词 |
| 粗体条目复读 | `- **性能：** 性能提升了` | 三条列表零信息 | 写数字与对比对象，或删条目 |
| 万能限定词 | `通常`、`必要时` 修饰硬约束 | 无法判断是否满足 | 写触发条件；写不出就登记内容缺陷 |
| 混层 | 需求条目里写签名与线程模型 | 分不清约束和实现选择 | 移到设计层 |
| 无锚点断言 | “如设计所述”“见相关章节” | 全文搜索才能核对 | 补 ID 或章节路径 |
| 该表未表 | 三项以上并列写成长段 | 手工做对照表 | 改表格，每列一个维度 |
| 表格塞长句 | 单元格里是一段推导 | 表格失去对照价值 | 单元格只放取值、ID、阈值 |
| 上下文重复 | 每章重述 change 身份与目标 | 多处真相需要交叉核对 | 只留 `change.json` 一份 |
| AI 腔收尾 | “综上所述，本方案在……的同时……” | 结论重复且不可证伪 | 删整段 |
| 无来源猜想 | “未来可以扩展为……” | 分不清承诺还是联想 | 删掉或登记 `EXC-xxx` |

## 1. 空转句

**识别**：整句删掉后，读者的判断不变。常见于章节开头和结尾。

**代价**：评审者读完一段却没得到任何可以反对的东西，只能默认通过。

```markdown
❌ 本次变更对配置模块进行了优化，在保证兼容性的前提下提升了健壮性与可维护性。
✅ 配置校验失败时，模块保留上一份生效配置并返回 `ERR_CONFIG_INVALID`；
   原行为是清空配置继续启动。
```

## 2. 模板复读

**识别**：`delta-design.md` 的“风险与回滚”写着“本节描述风险与回滚措施”，然后没有风险；或章节正文逐句复述模板的填写说明。

**代价**：评审者无法区分“分析过、确实不适用”和“没分析、拿模板凑数”。

```markdown
❌ ## 数据迁移
   本节用于描述本次变更涉及的数据迁移与回滚方案。
✅ ## 数据迁移
   N/A：本次变更不改动持久化结构，`config_blob` 的字段与版本号保持 v3。
   证据：DD-004 的 selector 只覆盖内存缓存路径。
```

N/A 要可审查：说清楚为什么不适用，给出可核对的锚点。

## 3. 结论后置

**识别**：段落前两句是历史、背景、讨论过程，判断在最后一句。

**代价**：评审者必须读完每一段才知道这段要不要细看，审查时间成倍增加。

```markdown
❌ 配置模块最早在 2019 年引入……随着设备形态增加……经过评估……
   因此本次变更决定保留上一份生效配置。
✅ 本次变更把配置加载失败的行为改为保留上一份生效配置。
   触发缺陷：DEF-1183，弱网重启后标定参数丢失。
```

## 4. 术语漂移

**识别**：同一对象在文中出现两个以上名字；或同一个词一会儿中文一会儿英文。

**代价**：评审者要先建立同义词映射，才能判断语义是否一致；映射猜错会直接放过语义冲突。

```markdown
❌ 会话建立后……链路保持期间……该连接超时后释放上下文。
✅ 会话（session）建立后……会话保持期间……会话超时后释放上下文。
```

修法：统一用词，首现给中英对照，易混术语超过三个时加术语表（见 `zh-writing-rules.md` 第五节）。

## 5. 代词悬空

**识别**：`其`、`它`、`该模块`、`这一部分`、`上述流程` 跨句或跨段出现，且上文有两个以上候选对象。

```markdown
❌ 接口调用前需要保证其已完成初始化，否则它的状态可能不一致。
✅ 调用 `config_apply()` 前必须先调用 `config_init()`；未初始化时返回 `ERR_BAD_STATE`。
```

## 6. 名词化长句

**识别**：一句 60 字以上；动作被写成“对……进行……的处理/操作/管理”。

```markdown
❌ 系统需要实现对下发配置数据的完整性校验处理，并在校验未通过的情况下完成对
   非法配置的拒绝以及对当前生效配置的保持。
✅ 校验下发配置的 CRC32。不匹配时拒绝该配置，保持当前生效配置不变。
```

## 7. 粗体条目复读

**识别**：列表项形如 `- **X：** X 得到了提升/增强/优化`。

```markdown
❌ - **性能：** 性能得到提升。
   - **可靠性：** 可靠性有所增强。
✅ | 维度 | 变化 | 证据 |
   |---|---|---|
   | 启动耗时 | 120 ms → 45 ms | TC-014 |
   | 弱网重启保留标定 | 丢失 → 保留 | TC-018 |
```

## 8. 万能限定词

**识别**：`通常`、`一般`、`原则上`、`必要时`、`尽可能`、`合理的`、`适当的` 出现在需求、契约或阈值附近。

**代价**：这类词让条目看起来完整，实际不可验证；它是内容缺陷伪装成措辞问题。

处理：不改写、不换词。保留原文，登记 Open Question 或 finding，写明去向（`devflow-specify` 补阈值与来源，`devflow-design` 补契约与时序）和 owner。

## 9. 混层

**识别**：需求条目里出现函数签名、数据结构、线程原语、库名；或设计里重新定义验收阈值。

**代价**：评审者分不清哪些是必须满足的约束，哪些是本次选择的实现手段，导致后续变更误以为签名也是合同。

```markdown
❌ FR-012：系统 SHALL 通过 `std::mutex` 保护 `config_cache_` 并在 50 ms 内返回。
✅ FR-012：WHEN 收到并发 SetConfig 请求 THE 配置模块 SHALL 串行生效并在 50 ms 内返回结果。
   （锁的选择放到 delta-design.md 的实现设计，由 DD-006 承载）
```

## 10. 无锚点断言

**识别**：“如设计所述”“见相关章节”“参考前文”“按既有约定”。

```markdown
❌ 该行为在设计文档中已有说明。
✅ 见 `specs/design.md` 的 `4.2 配置持久化`；本次由 DD-007 局部修改其错误分支。
```

## 11. 该表未表 / 表格塞长句

**识别**：三项以上并列且维度相同，却写成长段；或表格单元格里是整段推导。

```markdown
❌ 方案 A 改动小但扩展性一般，方案 B 扩展性好但要改三个调用方且需要新的迁移脚本，
   方案 C 介于两者之间。
✅ | 方案 | 改动范围 | 迁移成本 | 结论 |
   |---|---|---|---|
   | A | `config_store` 一个文件 | 无 | 推荐（DEC-003） |
   | B | 三个调用方 + 迁移脚本 | 需停机窗口 | 否决：超出本 AR 范围 |
   | C | 两个文件 | 无 | 否决：与 A 同效果但多一层间接 |
```

## 12. 上下文重复

**识别**：多个章节重复 change 身份、`baseRevision`、profile、门禁状态或本次目标。

**代价**：产生第二处需要核对的“真相”，且几乎必然与 `change.json` 不同步。

修法：删除重复，正文只在需要时引用 ID。

## 13. AI 腔收尾

**识别**：章节末尾出现“综上所述”“总的来说，本方案在保证……的同时……”“这不仅……而且……”。

修法：整段删除。结论应当已经在章节开头。

## 14. 无来源猜想

**识别**：“未来可以进一步扩展为……”“后续可考虑支持……”，没有单据、没有 ID。

**代价**：评审者无法判断这是承诺、计划还是联想；实现者可能照着做，导致投机抽象。

修法：删掉；确有计划时登记为 `EXC-xxx` 或新 AR，写明去向。

## 使用顺序

扫描时按“先结构、后句子、最后格式”的顺序，避免在还要重排段落时纠结空格：

1. 结构层：模板复读、结论后置、上下文重复、AI 腔收尾、该表未表。
2. 语义层：术语漂移、代词悬空、混层、无锚点断言、无来源猜想。
3. 句子层：空转句、名词化长句、粗体条目复读。
4. 格式层：中英空格、标点、单位与统计口径。
5. 全程旁路：万能限定词一律登记为内容缺陷，不在改写中消化。
