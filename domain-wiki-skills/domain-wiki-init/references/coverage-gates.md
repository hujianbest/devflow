# 覆盖门禁

「成页」= 独立的概念 Markdown 文件，带 OKF `type`。栏目总览里的表格、清单、一节标题 **不算成页**。

盘点出多种接口族、界面或跨模块流程时，容易收成一张表并声称已经覆盖。那是失败。能用的领域 wiki靠这些面各自有页。

## 大仓必拆

盘点一旦看到下列**表面类型**，骨架必须建成 **目录 + overview + 每面一页**。不得收成仓库根上的单文件。路径名随仓库改，不要按某一类框架的目录名凑。

| 盘点信号 | 必拆单位 | 失败形态 |
|---|---|---|
| ≥3 个有独立契约的接口族（HTTP / RPC / GraphQL / CLI 子命令族均可） | 每个族一页 | 一张「接口清单」表 |
| ≥3 个独立界面（应用、控制台、管理端、主要页面族） | 每个界面一页 | 一张「页面与入口」表 |
| ≥2 个跨模块的命名流程或用例 | 每个流程一页 | 一个总览文件里两节 |
| ≥2 个有独立不变量的领域模块 | 每个模块一页 | 只写模块地图 |
| ≥2 份架构决策记录 | 决策汇总页（或同等） | 只在 overview 提一句 |
| ≥3 个共享契约或内核文件 | 共享层概述（或按组分页） | 完全不提 |
| 有权威 schema 或写所有权边界 | 数据概述页 | 只埋在某一个存储适配器页 |
| 构建/运行入口不止一条，或环境变量影响行为 | 工具与运行页 | 只在 quickstart 写一条启动命令 |

小仓（大约不超过 10 个主源）仍可 `quickstart` + 1–2 页，不受上表约束。

## 允许合并的只有这些

- 目标架构有名、磁盘无实现（空模块、空适配器目录）。
- 占位路由、遗留平行入口、未提交切片的附注（可挂在所属族的页上，标 `source-backed`）。
- 真薄页：没有独立不变量，写出来会只剩文件名列表。

「我已经在总览里列了」不是合并理由。覆盖评审遇到必拆单位被收成表，记为必改项，不得标「已接受的合并」。

## 写完怎么验

对 inventory 里的每个必拆单位，本 wiki 根里要有对应路径。缺一条，init/completeness pass 就还没完成。
