# HTTP API 契约

## 已声明操作

| 项目 | 契约值 |
|---|---|
| 方法与路径 | `POST /orders/{orderId}/cancel` |
| `operationId` | `cancelOrder` |
| 路径参数 | `orderId`，必填，类型 `string` |
| 200 | `Order cancelled` |
| 409 | `Order cannot be cancelled in its current state` |

证据：`openapi.yaml:1-19`。

## 契约可保证与不可保证的边界

### 契约中明确声明

- 取消通过 POST 操作表达。
- 调用需要路径中的字符串订单标识。
- 契约允许成功和当前状态冲突两类响应。

### 契约中未定义

- 请求体、请求头、取消原因或认证要求；
- 200 和 409 的响应体与媒体类型；
- 订单不存在、无权限、参数格式错误和服务故障的响应；
- 幂等键或重复请求语义；
- `orderId` 的格式、长度和大小写规则；
- 退款、库存、通知或事件发布；
- API 路径版本策略。

## 契约与 Python 实现的映射状态

| 映射问题 | 结论 |
|---|---|
| `orderId` 如何加载 `Order` | 未实现/未提供证据 |
| `cancelOrder` 是否调用 `OrderService.cancel` | 名称与意图一致，但无调用链证据 |
| `ValueError` 如何映射到 409 | 未实现/未提供证据 |
| 成功对象如何形成 200 响应 | 未定义 |
| 变更如何持久化 | 未定义 |

因此，HTTP 操作是**契约事实**，内存状态变更是**实现事实**，但“HTTP 端点可用”不是当前材料支持的事实。

## 候选契约改进（非当前事实）

- 为 200/409 定义稳定的响应 schema 和错误码。
- 明确 404、401/403、422 与 5xx 行为。
- 明确重复取消和并发冲突语义。
- 如果取消需要原因，定义请求体；如果不需要，明确空请求体。

这些是设计候选项，须经 API 和业务负责人评审。
